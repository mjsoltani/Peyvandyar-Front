## ۵. لاگ سینک متن خطای باسلام را ذخیره نمی‌کند

## ۶. (امنیتی) نشت توکن غرفه فرزند

`GET /api/parent-child/children/:parentVendorId` برای هر فرزند فیلد `child_token_hash` را برمی‌گرداند. مقدار آن **دقیقاً همان توکن پیوندیار فرزند** است (همان مقداری که در هدر `X-Encrypted-Token` استفاده می‌شود)، نه یک hash. یعنی صاحب غرفه والد می‌تواند با این مقدار وارد حساب غرفه فرزند شود و هر عملیاتی انجام دهد.

**درخواست:**
- `child_token_hash` (و هر توکن دیگری) از پاسخ این endpoint و سایر endpointهای parent-child حذف شود.
- چون این مقدار قبلاً به کلاینت‌ها ارسال شده، بهتر است توکن‌های فرزندهای موجود باطل/چرخانده شوند.

## ۷. کپی محصول با `403` برای کاربری که `basalam_vendor_id` ندارد

کاربر: 09933647282، user_id 3348.

- `GET /api/me` و `GET /api/user/status`: مقدار `basalam_vendor_id` / `vendor_id` برابر `null`.
- `GET /api/vendor-id` (از باسلام): `{"vendor_id":1706029,"vendor_title":"سام گلد","vendor_identifier":"sam-gold"}`.
- `GET /api/product/{id}` برای هر ۲۶ محصول درخواستی: `200`.
- `POST /api/product/58811291/copy`:

```json
{"success":false,"status":403,"message":"شما دسترسی لازم برای انجام این عملیات را ندارید.","details":{"detail":"Forbidden"}}
```

`details.detail` فرمت خطای باسلام است، یعنی بک‌اند خطای باسلام را عیناً پاس داده. احتمالاً کاربر قبل از داشتن غرفه وارد پیوندیار شده؛ پس vendor ذخیره نشده و توکن OAuth او scope نوشتن محصول ندارد. فراخوانی `/api/vendor-id` هم vendor را در DB ذخیره نمی‌کند.

**درخواست:**
- اگر `basalam_vendor_id` خالی است، قبل از کپی از `/v1/users/me` باسلام گرفته و ذخیره شود (`/api/vendor-id` هم می‌تواند همین کار را بکند).
- اگر توکن scope لازم را ندارد، خطای مشخص (مثلاً `code: "REAUTH_REQUIRED"`) برگردانده شود تا فرانت به کاربر بگوید دوباره وارد شود.

## ۱۰. کپی محصول طلا/سکه با `422` روی `product_attribute` — کاربر از UI نمی‌تواند کپی کند

تاریخ: ۱۹ مهر ۱۴۰۵ (2026-10-11)

کاربر: `09933647282`، غرفه «سام گلد»، `basalam_vendor_id=1706029` (الان در `/api/me` ست است؛ دیگر حالت issue ۷ نیست).

### علائم در UI پیوندیار

- `POST /api/product/{id}/copy` (همان endpoint صفحه `/dashboard/copy-product/basalam`)
- `POST /api/products/copy-selected`

برای محصولات دسته طلا / شمش و پلاک طلا (مثلاً `category_id=1079`) شکست می‌خورند. پیام سطح بالا اغلب این است:

`این محصول قبلاً کپی شده یا رکورد تکراری است.`

ولی `details` واقعی باسلام:

```json
{
  "http_status": 422,
  "messages": [
    {
      "message": "برخی از ویژگی های محصول اجباری وارد نشده است",
      "code": 0,
      "fields": ["product_attribute"]
    }
  ]
}
```

ویژگی‌های اجباری نمونه برای این دسته:

| attribute_id | عنوان |
|---|---|
| 1786 | وزن طلا (میلی گرم) |
| 1785 | عیار طلا (مبنای 1000) |

روی بعضی محصولات مبدأ (`attribute_groups` خالی است) بک‌اند اصلاً مقداری برای ارسال ندارد و باز هم `422` می‌دهد.

وقتی فرانت/`product_data` دستی هم `product_attribute` بفرستد، کپی همچنان خراب است چون:
1. شناسه عکس غرفه مبدأ برای غرفه مقصد معتبر نیست (`fields: ["photo"]` → «شناسه تصویر موجود نیست»)
2. مسیر copy ظاهراً `product_attribute` را درست به OpenAPI باسلام نگاشت نمی‌کند

### مسیر جایگزین که کار می‌کند (workaround عملیاتی)

همین محصولات با این فلو ساخته شدند (نه با `/copy`):

1. `GET /api/product/{id}` — خواندن منبع  
2. دانلود عکس `photo.original` و `POST /api/products/upload-image` → `image_id`  
3. `POST /api/products` با بدنه شامل حداقل:

```json
{
  "name": "...",
  "photo": "<image_id>",
  "photos": ["<image_id>"],
  "primary_price": 123,
  "stock": 10,
  "category_id": 1079,
  "product_attribute": [
    {"attribute_id": 1786, "value": "40"},
    {"attribute_id": 1785, "value": "750"}
  ],
  "package_weight": 100,
  "weight": 40,
  "preparation_days": 3,
  "description": "..."
}
```

اگر `attribute_groups` مبدأ خالی بود، وزن از عنوان (مثلاً `100 سوت`) و عیار `750` پر شد؛ در چند مورد retry با `category_id=1236` (سکه بانکی) هم جواب داد.

### درخواست از بک‌اند

1. در `POST /api/product/:id/copy` و `copy-selected` / `copy-from-booth`:  
   - عکس را برای غرفه مقصد دوباره آپلود کنید (reuse id مبدأ نکنید).  
   - `product_attribute` اجباری دسته را از `attribute_groups` مبدأ بسازید و به OpenAPI بفرستید.  
2. اگر مبدأ attribute ندارد، یا از عنوان/وزن/unit استنباط کنید یا خطای واضح با لیست فیلدهای اجباری برگردانید (نه پیام «قبلاً کپی شده»).  
3. پیام generic «قبلاً کپی شده یا رکورد تکراری» را فقط وقتی بزنید که واقعاً duplicate باشد؛ برای `422` باسلام همان messages را به فرانت پاس دهید (`code` جدا مثل `BASALAM_VALIDATION`).
